# Комментарии

**Default — не писать комментарий.** Хорошее имя функции/класса/переменной и тип уже объясняют
WHAT. Комментарий допустим, только если без него читатель не догадается о **WHY** — скрытый
инвариант, неочевидное ограничение, workaround под конкретный баг, поведение, которое удивит.
Module-docstring — одна-две строки про роль файла; не эссе.

## Запрещено

- **Restate WHAT.** `# грузит профиль по id` над `load_profile` — нет. Тип и имя уже всё сказали.
- **Narration.** Многострочный пересказ «сначала X, потом Y, наконец Z». Код это и так показывает.
- **Архитектурные эссе в docstring.** Pattern/принципы/слои — место `design/`/`docs/`/`CLAUDE.md`,
  не рядом с реализацией (особенно `provider.py`/`__init__.py`).
- **Tombstones.** `# убрали XXX`, `# раньше было Y` — нет, для этого `git log`.
- **Ссылка на задачу/PR.** `# для флоу X`, `# fix #123` — в commit message / PR, не в коде.
- **Flavor-комментарий.** Художественный пересказ того, что и так видно в коде.
- **TODO без контекста.** `# TODO: fix` бесполезен. Оставляешь TODO — дай owner/ticket/condition.
- **Section dividers** как украшение. `# ──── helpers ────` поверх ясной структуры — лишнее
  (раскладка по группам провайдеров в `app.py` — исключение: ведёт last-wins-порядок).
- **Закомментированный код.** Удали — он в `git log`.

## Допустимо (одна короткая строка, WHY)

- Инвариант: `# /start ВСЕГДА RESET_STACK: иначе стек копится до 100 → DialogStackOverflow.`
- Workaround: `# router._parent_router = None — детач module-level dialog между тестами.`
- Сюрприз: `# LogkitProvider ПОСЛЕ BotProvider (его дефолт nop иначе победит).`
- Хитрая константа/дедлайн: `# deadline=9.0 < 10с дедлайна Telegram на pre_checkout (fail-closed).`

## Чек

Больше **одной строки** — почти наверняка лишнее: вырази именем/структурой, а «почему так» — в
`design/`/`docs/`, не в `.py`. После правки глянь diff: добавленный комментарий объясняет
невидимое из кода? Нет — удали. (Логи — `logkit.Logger`, не `print`; забанено ruff T20.)

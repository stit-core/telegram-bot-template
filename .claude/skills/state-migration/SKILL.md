# Skill: state-migration

Процедура безопасного изменения `platform/dialogs/states.py` (и связанных окон) на **живом** боте. Уникальная боль aiogram_dialog: dialog-stack пользователя хранится в Redis и **ссылается на `State` по имени/пути**. Удалил/переименовал/переместил живой `State` → у юзеров в открытых диалогах нет на что приземлиться: апдейт прилетает → `UnknownState`/`UnknownIntent`/`OutdatedIntent`. Откат образа это **не лечит** (их стек в Redis уже указывает на исчезнувший State).

Поэтому правило: **эволюция через deprecation, не через удаление**. Этот скилл — чек-лист, как это сделать. Якорь — rule `state-lifecycle` (грузится на `platform/dialogs/states.py`).

## Когда применять

- Удаляешь/переименовываешь/перемещаешь `State` или `StatesGroup` в `platform/dialogs/states.py`.
- Меняешь флоу так, что окно исчезает или его `state=` меняется.
- Разбираешь волну `UnknownState`/`UnknownIntent` в проде после деплоя.
- Прунишь фичу с её StatesGroup на **уже задеплоенном** боте (на свежем форке до первого деплоя — это просто `de-template prune`, не сюда).

## Когда НЕ применять

- **Добавление** нового `State`/`StatesGroup` (аддитивно, безопасно) → `scaffold window`/`feature`. Сюда — только удаление/переименование/перемещение существующего.
- Бот ещё не деплоился (нет живых стеков в проде) — менять можно свободно (но startup-smoke всё равно прогони).

## Что безопасно / опасно

| Операция | Безопасно? | Почему |
|---|---|---|
| Добавить `State` в группу | ✅ | старые стеки его не используют |
| Добавить новую `StatesGroup` | ✅ | аддитивно |
| Изменить **содержимое** окна (текст/кнопки/getter) при том же `state=` | ✅ | стек ссылается на State, не на разметку |
| Переименовать `State`/`StatesGroup` (Python-имя) | ⚠️ опасно | путь State меняется → живые стеки осиротеют |
| Удалить `State`/`StatesGroup` | ⚠️ опасно | живые стеки приземляются в никуда |
| Переместить `State` в другую группу | ⚠️ опасно | путь меняется (= удаление + добавление) |
| Поменять порядок `State()` в группе | ✅ обычно | aiogram идентифицирует по имени атрибута, не позиции — но проверь, не завязан ли код на порядок |

«Изменить контент окна» — самый частый и безопасный путь: если цель «другой текст/другая кнопка/другие данные» — **меняй разметку при том же `state=`**, State не трогай. Сюда (state-migration) идёшь, только если структура State реально меняется.

## Процедура (опасная операция)

### 1. Решить: правда ли нужно менять State?

Если задача решается изменением **контента** окна при том же `state=` — сделай так, State не трогай. Это выход из 90% случаев. Дальше — только если структура State обязана измениться.

### 2. Deprecation вместо удаления

Не удаляй/не переименовывай. **Оставь старый State**, помеченный deprecated, и добавь новый рядом:

```python
class Profile(StatesGroup):
    VIEW = State()
    EDIT_NAME = State()
    # DEPRECATED (since vX.Y.Z): осиротевшие стеки приземляются сюда → редирект на VIEW.
    # Удалить не раньше, чем истечёт TTL dialog-context в Redis + запас (см. §5).
    OLD_STEP = State()
    NEW_STEP = State()  # новое окно вместо OLD_STEP
```

- Новый флоу ведёт на `NEW_STEP`.
- `OLD_STEP` остаётся с окном-редиректом (см. §3), чтобы юзер, застрявший на нём, мягко перешёл.
- Переименование = тот же приём: старое имя оставь как deprecated-алиас/редирект, новое заведи.

### 3. Error-handler / редирект как сеть

Две сети одновременно:

- **Окно-редирект на deprecated State.** Для `OLD_STEP` оставь окно, чьё единственное действие — увести вперёд/в безопасную точку:
  ```python
  old_step_window = Window(
      I18NFormat("common-updated-restart"),  # «мы обновили этот шаг»
      Start(I18NFormat("common-to-menu"), id="redir", state=states.Start.MENU),
      state=ProfileSG.OLD_STEP,
  )
  ```
- **`ErrorUX` как глобальная сеть.** Убедись, что `platform/dialogs/errors.py` (`AppErrorUX`) на `on_unknown_state`/`on_unknown_intent` гасит callback и подсказывает `/start` (а `/start`=RESET_STACK пересоздаёт стек). Это ловит случаи, которые редирект не покрыл. Не трогает само сообщение (могло быть удалено).

Цель: **ни один живой стек не должен привести к необработанному `UnknownState`** — либо приземляется в deprecated-редирект, либо ловится `ErrorUX`.

### 4. Startup-smoke (обязательно)

После правки `states.py`/окон:
```bash
uv run pytest -k collision -q     # test_composition: setup_dialogs без коллизий StatesGroup
```
Ловит: дубль `state=`, два Dialog на одну группу, окно без `state=`, осиротевший State без окна. Красное — почини до коммита.

Добавь/обнови flow-тест: вход на старый путь приземляется в редирект (не падает); новый путь работает.

### 5. Окно удаления deprecated State (потом, отдельным релизом)

Deprecated State можно **физически удалить** только когда в Redis не осталось стеков, на него ссылающихся:
- dialog-context имеет TTL (rule `storage-serialization`; контексты пишут `{}`, чистятся по TTL). Дождись истечения TTL + запас (обычно следующий релиз через дни/недели).
- удаление deprecated State — это **отдельный** коммит/релиз, не в одном с введением нового. major-bump (см. `release`), т.к. снимает сеть.

### 6. Версионирование

- Введение нового State + deprecation старого — minor (аддитивно + сеть).
- Удаление deprecated State (снятие сети) — major.
- Помечай deprecated комментарием `# DEPRECATED (since vX.Y.Z)` — видно, когда можно удалять.

## Если разбираешь инцидент `UnknownState` в проде

1. Логи задеплоенного бота (stdout контейнера / агрегатор проекта) на `UnknownState`/`UnknownIntent` — масштаб, с какого деплоя началось.
2. Что в последнем релизе тронуло `states.py`? `git log -p -- src/bot/platform/dialogs/states.py`.
3. Нашёл удалённый/переименованный живой State → **верни его как deprecated** (§2) + редирект (§3), выкати фиксом. Откат образа не поможет.
4. Проверь `ErrorUX` ловит остаток (юзеры на полпути).

## Anti-patterns

- ❌ Удалить/переименовать живой State «чтобы стало чисто» — сломаешь открытые диалоги в проде.
- ❌ Удаление State и введение замены в одном релизе без deprecation-окна.
- ❌ Расчёт «откатим образ, если что» — откат не возвращает осиротевшие стеки в Redis.
- ❌ Менять `state=` окна, когда нужно лишь поменять его текст/кнопки (трогай разметку, не State).
- ❌ Снять deprecated State до истечения TTL живых контекстов.
- ❌ Коммит правки `states.py` без `pytest -k collision`.
- ❌ Оставить `ErrorUX` без обработки `UnknownState`/`UnknownIntent` — сеть дырявая.
